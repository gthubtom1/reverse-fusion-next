# 数据库配置、约束与备份核查

## 输入

收集引擎及版本、关联到同一实例或快照的模式、迁移、约束、角色/授权、审计设置和业务口径。备份题另收清单、摘要、锚点及增量序号。SQLite 记录 `user_version`，有 WAL 时获取同一时点一致性副本并记下捕获方式。原件只读保全。

## 判读

1. 按引擎、实例、库、模式和对象名配对。区分迁移文件的预期结构、快照实际结构、生产实例状态。逐项核对列类型与默认值、排序规则、NULL 语义、唯一或部分索引谓词、检查/外键约束和级联。数据库配置核查同时区分导出配置、继承和会话覆盖值。SQLite 外键检查受连接设置影响，试写时记录 `PRAGMA foreign_keys`。
2. 仅需检查结构时使用只读结构观察。确需验证业务约束时，对每版每个场景使用同一初始状态的独立可丢弃副本。记录完整输入、接受或拒绝、错误、提交后行集与原件摘要。分别给出旧版实际接受情况、新版实际接受情况、业务是否应接受。
3. 备份按引擎规定的基线、标识和日志范围串起全量及增量；核对连续性、摘要和目标恢复点。登记由清单推得的候选点。需要证明可恢复时，在独立环境恢复并查询关键表和行，记录恢复出的实际时间点。

## 核对

回读实际索引定义、谓词、连接选项和测试后行集。拒绝试写还要检查状态无额外变化。恢复结论核对起始全量、每段衔接和回读数据。生产状态缺同实例观察时标 `unknown`。交付表给出各版、各输入、结果、业务预期及依据。

## 反例

SQLite 普通唯一索引允许多条键含 NULL 的记录，业务却可能把空批次归为同一批。用两个空批次的同货号试写副本，数据库接受和业务应拒绝可以同时成立。备份摘要齐全但中间增量缺失时，该段之后的目标恢复点仍缺证据。
