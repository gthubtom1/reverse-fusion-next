# 常见离线材料核查

## 输入

取用户指定的本地材料及适用说明，记下摘要、版本、对象标识、时点和实际覆盖。归档以成员、清单和版本记录为依据。记录解码或换算使用与目标修订匹配的字段手册及公式。比对时给左右材料分别编号。

## 判读

| 材料及问题 | 核对依据和产出 |
|---|---|
| 两份安装包、资源包或扩展包 | 以成员精确路径、字节数、摘要比较新增、移除和内容变化。重复路径或路径解释不明确时保留歧义。清单与实际包成员分别列证据。MV3 分列必需站点、可选站点、必需 API、可选 API。先读 service worker 和弹窗的声明，再核对成员及摘要。真实打开与后台活动引用独立运行记录。 |
| APK、plist、PE/ELF 头、网页或 Flutter 静态导出 | 绑定同一制品摘要，再列明确读到的构建标识、声明字段、入口、外部资源或类型关系。标题、文件名和命中字符串仅作线索。用类型化记录及同构建独立参照复查归属。 |
| API 规范、新旧样本或已导出帧 | 规范按方法、路径、请求字段与类型、必填性和响应条件比较。已导出帧另核封装、长度、偏移、字节序、格式版本、时间及单位。区分声明长度和可用字节。列明未覆盖的字段、截断和解释范围。 |
| 字段手册与 `[字段编号, 值]` 记录 | 按同版本手册解析字段和单位。`field_decode_records` 可返回映射行和各字段统计。按用户问的对象、单位和范围汇总，区分记录数、已知数量和未确认的数量。 |
| 设备、分区或固件版本清单 | 用同一快照的分区到版本映射解释 `active` 与 `next_boot`。区分现装、计划切换和日志确认已启动。模型或名称相同的其他设备单列。 |
| 校准和工程台账 | 绑定公式与适用修订，保留原值、比例、偏移、运算顺序及单位。缺少运算顺序时给出适用条件和候选计算，工程值记 `unknown`。缺单位时单独标明。 |
| 业务评测、覆盖或巡检记录 | 绑定对象、时段、工具和规则修订、分母以及原始记录 ID。列出已核对、未覆盖和无法解释的项。汇总表注明覆盖范围，保留源记录位置。 |

## 核对

从交付物回查每个标识属于哪个原件。至少分别检查一个有效空值和一个缺失项。抽查 ZIP 成员内容摘要、字段映射和值，复算一个边界记录及一次工程换算。负面结论注明可观察范围。图表或报告从保存的文件回读，确认编号、文字和证据一致。

## 反例

ZIP 内有 `background.js`，清单未声明 worker，报告可以确认文件存在，worker 的实际后台运行仍为 `unknown`。另如 `raw=10`、`scale=2`、`offset=3`，两种常见顺序分别得到 23 与 26，需依据适用修订的计算式选值。分区清单的 `next_boot=B` 只支持下一次启动的计划项。
