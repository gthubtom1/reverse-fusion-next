# 供应商召回与依赖影响核查

## 输入

取带修订号的召回公告和适用时点、现装或部署清单、对应批次用料表或可定位到制品的锁文件/SBOM，以及换装记录或厂商修复声明。每件材料记录来源、摘要、出具时间和行号或字段路径。先确定要判定的是设备、部署批次还是构建。

## 判读

1. 逐条把目标对象映射到截点当时的现装批次或实际部署制品，优先核对可绑定现场记录的标识。再从同批次用料或同制品依赖解析结果取得供应商、产品坐标、组件版本、批次和制品摘要。旧台账、计划版本和未部署构建只作为历史。
2. 按公告定义匹配供应商、生态、命名空间、部件号及适用渠道。版本比较采用该生态或公告规定的规则，明确下界和上界是否包含、预发布和发行修订的处理。回移修复须有明确标识，且该标识能绑定到已部署制品。
3. 用公告口径逐对象填 `受影响`、`排除`、`已修复` 或 `待核`，同时列出判定时点、依据和下一步。已确认同一受影响坐标且命中条件才判受影响。排除引用明确的不匹配条件或完整库存证明。已修复要求实际部署记录和对应修复依据。关键连接缺失或互相冲突时登记待核。

## 核对

按 `对象 ID → 现装批次/制品 → 组件坐标及版本 → 公告条款 → 处置` 回查，确保类别合计与目标清单一致。重算边界版本和替代版本，单列有待核记录的分母。对同名部件、旧批次、区间上界及未登记制品各抽一个反例。发布修复的时间与现场完成更换的时间分列。

## 反例

公告只召回甲供应商 `BZ-14` 的 `>=2.9.2`、`<2.10.0`。在公告的整数段口径下，`2.9.10` 命中，`2.10.0` 排除。同号乙供应商也排除。设备已换到用料表未覆盖的新批次时，结论待核，旧批次记录仍可随报告保留。
