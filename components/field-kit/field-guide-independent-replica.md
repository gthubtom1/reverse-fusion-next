# 从可操作原件独立复刻

## 输入

记录用户要求的交付范围、可操作的原件及其版本与摘要、运行载体、依赖和可用操作。保留可独立启动原件及候选的环境和独立数据目录。已有规格、截图、导出文件和观察记录各自标记身份。若材料仅静态，先标出缺证行为与需要继续确认的范围。

## 判读

1. 从原件实际走完代表操作，形成 `场景 ID / 初始状态 / 操作序列 / 可见结果 / 重开后状态 / 导出或日志 / 观察条件`。覆盖初启、保存、重开、编辑、清空、取消、无效输入和常见边界，按业务确定优先级。载体特有行为也要单列，例如浏览器扩展的工具栏徽章、页面入口和权限声明。
2. 从已观察行为构建独立源工程，保留构建和启动说明、依赖版本及未知项。独立复刻、按规格实现、修改原程序与仅交付报告分别归属到用户选定目标。记录证据矛盾和缺失，保持用户要求的完成范围。
3. 两侧分开启动，用同一序列和输入分别记录实际输出。对页面与桌面外观单列显示参数及截图对照。对业务状态检查保存、重启和后续操作结果。导出按要求比较原始字节、编码、换行、列序与边界记录。结果登记通过、差异或未知，附两侧实际证据。

## 核对

每次修正关联前后制品和差异证据。用同一失败用例复查，并另用未用过的数据发现共享假设。变动影响到的旧对照重新做。交付需要可重建时，在干净目录按交付说明重建，比较成品和重建件的真实行为。量化已核对的场景，保留依赖未满足的项。

## 反例

两侧弹窗截图相同，候选里的保存内容重开后丢失，或工具栏徽章没有更新。视觉结果可通过，持久化或载体行为仍失败。原件结果缺失或两份实际输出都为空时，须先核对测试是否真正走到了观察点。
