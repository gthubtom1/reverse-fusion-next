# 云身份、目录与联合配置核查

## 输入

收集带修订和时点的提供方及目标应用配置、账户和组成员快照、角色绑定、组织或资源继承规则、规则有效期，以及用户明确要求核对的主体和资源。使用稳定主体及组 ID。若已有同版本的登录或授权审计记录，记录可定位的事件 ID。

## 判读

1. 按协议把配置绑定到目标应用。OIDC 检查提供方 `issuer`、接受的 `audience` 或关联客户端、声明映射以及配置值比较方式。SAML 检查实体 ID、受众、接收端或回调约束、信任元数据和证书适用期。标记不同快照版本、环境或缺少可连接键的记录。
2. 按配置规则逐组合检查 `主体 → 直接或传递组成员 → 角色/规则 → 目标对象和动作`。组展开应用该目录的嵌套及作用域规则、识别循环，并区分普通组和动态组快照。核对拒绝、权限边界、资源层继承、条件及其真实优先级。将有效期归一化到核查时点，边界比较遵照题设或系统定义。
3. 列每个账户与每条规则的条件结果，保留 `符合配置 / 不符合 / unknown`。确定失败保持失败，无法决定的组合保留缺证字段。分别报告配置资格、已观察的登录结果和已观察的资源授权结果。

## 核对

从源配置逐条抽检精确 issuer、同名异 ID 的组、失效规则和继承条件。核对批准或拒绝记录是否能绑定同一主体、目标、时点及规则修订。目录导出不全时列出未覆盖的分支和受影响项目。

## 反例

同名 `Finance` 组的稳定 ID 不同，只有配置中引用的组参与判断。快照表明组条件和有效期均满足时，只能直接写“配置资格满足”。缺少同一主体和时点的鉴权记录时，实际登录仍为 `unknown`。
