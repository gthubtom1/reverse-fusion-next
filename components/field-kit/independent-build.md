# 独立实现与行为对照

先找到可供观察的原件和独立的交付位置。列出用户能完成的操作、输入约束、可见状态、持久状态和导出格式。从用户实际看到的界面开始。存在可操作的展示台时可用它探索原件和候选，保存必要的观察。得到原件源码并逐行翻写不足以证明独立实现。

把新实现写进交付目录。分别从干净状态启动原件和候选，在两侧输入同一组业务数据。核对操作后的界面、关闭并重新打开后的数据、错误操作发生后的记录，以及实际下载文件的内容、标点、编码和边界行。一次成功退出只对应那一次进程执行。

发现差异时记录输入、两侧输出和各自版本，修正候选，再用相同操作复核。最后换一组此前没用过的数据。对同一个原件换了输入也应留新观察。哪些误差可以接受取决于用户要求。图像、结构和业务行为各自如实报告。

此处采用 Craft 独立比较、修正和复核的原则，由当前宿主操作。显示器或实际业务工具按具体场景选择。

## 融合入口中的本地命令行对照

在融合源码中，助手可以调用 `fusion.py replay --project-root <项目目录> --plan plan.json --output runs/before --trusted-local`。仅在已审阅计划和两份本地程序时执行；独立工作副本不是操作系统沙箱。MCP 不接出这个执行入口。

计划使用 `version: 2`，用 `scope` 说明范围，`original` 与 `candidate` 各声明 `cwd`、`argv` 和入口等 `sources`，两份源码目录互不包含。每个 `scenarios` 项含唯一 `id` 和有序 `steps`；每步声明 `stdin`、`args`、`files`、`expected_exit_codes`，另在顶层声明 `timeout_seconds`。项目内路径使用 `/` 分隔。原始结果保存为 `runs/before/comparison.json`，并留下实际输出和声明的文件快照。修正后使用新的输出目录，例如 `runs/after`。

退出码 0 表示声明范围内相符，1 表示观测到差异，2 表示未判定或请求无效。保留前后回执，必要时在任务检查点记录回执、计划和源码路径。自有回执与官方 REA Bundle 分开保存；相符也只说明测过的场景相符。
