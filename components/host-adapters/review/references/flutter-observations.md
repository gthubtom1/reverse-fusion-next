# 如何解释已经导出的 Flutter 静态观察

先记下应用库的摘要、构建方式、工具名和版本。若两份观察对应不同的应用库，把它们当作不同输入。文件名相同不足以建立关联。

| 已有材料 | 可以写入报告 | 还需要什么才能再进一步 |
| --- | --- | --- |
| REA 的字符串字段命中一个名字 | 该字符串出现在指定输入 | 类型化记录才能把它归入某个类或函数 |
| AOTopsy 的类和库记录 | 解析器报告了这个类和它所属的库 | 对应构建的独立参照可用来核实身份 |
| 拆分调试信息后只有生成的函数名 | 保留工具报告的名字，原始名称记为未知 | 精确匹配该构建的独立符号或源码依据 |
| 两个导出的结构相同 | 两个文件在声明字段上相同 | 运行行为需要单独观察 |

来源是 SEEP 中采用的第三方 AOTopsy，以及本项目三个自编 Android ARM64 构建的既有对照。三个构建均识别出预期的类和库。拆分构建的四个指定函数名恢复了零个，普通构建的两个恢复了两个。保留第三方的身份和局限；阅读既有结果时按问题选择字段即可。
