# 零基础使用

安装一次后，在要开发的软件文件夹打开智能体，用自己的话描述。共享工具目录要保留，不用复制技能，不用记工具名。

- “帮我分析这里的软件，再做出功能和使用效果一样的版本。我不懂技术，需要我操作时请说清楚。”
- “这是我自己的APK，先帮我看懂怎么工作，目前只要分析报告。”
- “照这个网站做一个，外观和交互都要核对。缺后台资料请具体告诉我。”
- “帮我开发库存管理软件。”普通开发走正常流程，需要调查再调用领域工具。

有合法可用账号/卡密时说“我能正常进入，可以配合操作”；没有时说“目前进不去”。秘密不要写进报告。智能体先调查材料，再说明具体需要什么，不要求你选择调试/dump等专业方法。

补充说“刚才要求保留，再增加……”。中断说“继续上次”，智能体从已有可靠任务记录恢复；使用了可选case时恢复同case，不另造一套。可问“最开始的要求，还有哪些没做完？哪些实际比较过？哪些只是外部结果审查？”。

智能体自行判断当前缺什么信息、该用什么工具；不要求每次都使用REA或我们的流程。进不去、加壳或工具失败时先调查具体条件，静态、动态和实现可交替，不固定先绕授权或先Dump。独立重写、按规格实现和修改原程序是不同成果；技术路线可自行调整，交付类型变化要说明，不悄悄替换你的目标。

分析结束不代表复刻完成，外观相似不表示业务一致。不可观察的服务端行为列缺口，继续独立部分。换电脑让智能体按AGENT-BOOTSTRAP.md安装，核真实连接，再在成果项目对话。

## 临时文件不会一直堆积吗

2.4.0会在生成文件时分清三种用途：必须保留、可能复用、用完即删。
一批操作或验证结束时，智能体检查清理：一次性输出及时回收，有后续用途的缓存保留，
原软件、源码、有效证据和成果长期保留。多个项目共用磁盘时也会检查余量。
你可以直接说“文件请分级保存，每批操作结束时清理用完的临时内容，保留可能复用的材料和成果”。
无需自己挑工具或填写空间参数；不是每条命令后都打断工作。历史未登记目录保持原样，
活动中的任务不会仅因时间到了就被清理。详细规则见DISK-MANAGEMENT.md。
