# Reverse Fusion 本地分析候选

**你只要说材料在哪、想拿到什么。** 示例：「比较这两份本地文件。给我能确认的差异、每条的依据，以及还不能确认的部分。」路线、工具和格式由助手按任务选择；普通任务可以直接用助手原来的工具。

**试用本轮功能时用当前源码。** 旧 rc.2 下载包没有下面的四方交接功能，日常安装也未替换。

## 隔离试用

在 Windows x64、Python 3.11 或更高版本的环境中，从候选源码目录执行下面一行。它只写入指定的试用配置目录，不更改平常用的 Pi。

```powershell
python fusion.py setup pi --home "$env:LOCALAPPDATA\ReverseFusionTrial"
```

首次准备会核对锁定的 Node 和 REA 6.9.0 归档。若没有本地归档，需要网络。保留候选源码目录，助手从那里启动工具。下面两行分别检查和移除试用登记；移除保留原有配置和个人文件。

```powershell
python fusion.py check pi --home "$env:LOCALAPPDATA\ReverseFusionTrial"
```

```powershell
python fusion.py remove pi --home "$env:LOCALAPPDATA\ReverseFusionTrial"
```

其它助手有相同的安装接口：`claude`、`codex`、`opencode`。OpenCode Desktop 2.x 可用 `--opencode-version 2`，安装、检查和移除保持同一版本选项。试用时从安装结果找 `mcp_config`：Pi 在单独终端把 `PI_CODING_AGENT_DIR` 指向该文件的父目录；Codex 用同样方式为该终端设置 `CODEX_HOME`；OpenCode 可把 `OPENCODE_CONFIG` 指向该文件。Claude Code 则用安装结果中的 `skill` 目录作为 `--plugin-dir`。试用目录只包含融合的登记，不会带入日常设置、登录或扩展；用完关闭试用终端。准备日常接入前，先完成实际助手的接入和回退验证。

## 候选带来什么

- 官方 REA：选取适合本地分析的原生操作，保留其工具定义、实际结果和官方证据档案。非完整原版目录；特定分析仍取决于系统和工具依赖。
- Reverse 方法：助手可以按问题读取参考原文及文件指纹，或浏览已安装的方法索引；没有固定路线，也不是完整 Reverse 技能库。
- Craft 的对照做法：可以用 `fusion.py replay` 独立运行两份可信本地程序，保存差异和修正前后的结果。按需读取 `comparison` 方法可获得本机命令位置。只需对照现有文件时，可直接用字节比较。两者都是自有工具，不是官方证据。
- SEEP 方向的 Flutter 专项：助手可同时查适用的 ARM64 库的类归属和 REA 的 ELF 注记。两份观察用文件指纹对应；类归属是专项结果，官方证据只说明它观测到的 ELF 信息。应用运行行为仍是未知。
- 可选续接：保存原话、证据和下一步；重新打开后可找回。改动过的材料会标记为过期。

## 怎么判断做完

1. **装得上，退得回。** 同一版本从干净目录装到临时配置，助手实际识别它；移除后旧配置、旧文件都不变。
2. **能交真正的结果。** 用户只给一个没见过的本地任务，不背题目套路；有依据的结果、没有依据的猜测分开。要交程序时，故意做错的版本必须被对照查出。
3. **能接着做。** 用户换会话只说「继续」，仍能接回原任务、证据和下一步；材料有变时知道哪些旧结论要重查。

## 四方交接：同一任务的现场结果

任务是查两份自编 Flutter 库的类归属，并修正一段会把库名填错的导出程序。

1. 从融合入口选读取证参考，取得 Reverse Skills 原文和来源。REA 对两份库各生成官方 ELF 证据；Flutter 专项分别找到 `FixtureShelfV1` 和 `FixtureShelfV2` 所属的 Dart 库。两个结果各自与对应输入的 SHA-256 匹配。
2. 把实际查出的两条类归属交给独立对照。在包含两条记录的输入上，参考版输出库路径，错误版输出类名；对照查出标准输出不同。修正后这组与空输入均通过，修正前记录仍在。
3. 建立新连接。原任务、检查点和官方证据恢复，原生记录逐条一致；修改导出源码后检查点被标为过期。

[测试源码](../../tests_next/test_fusion_handoff.py)实际调用锁定的 REA 6.9.0、本地读取器和两个独立运行的 Python 程序。合成库是本项目自编的测试样例，不随源码提交；本机没有两份构建时，测试会跳过完整 Flutter 交接用例。输入指纹：V1 `065c002dad0a572ce0bbf4fa63dd2cd0d201e2aa199cc30f8ee2ad169557dea6`；V2 `476227d6fddf99a04c0f4b5fb3d9ead548574f78f2207d117a84a37ebd9bd126`。

```powershell
python -B -m unittest -v tests_next.test_fusion_handoff
```

当前源码 67 项回归通过，覆盖功能交接、有限对照、Field 和五套临时配置的接入与移除。本次测试由测试代码选择工具；四个助手在真实对话中是否自主选对工具、是否比裸助手答得更准，仍未验收。

## 旧版候选的覆盖范围

- 对照两个发布包，准确列出新增、移除和内容变动的文件。
- 对 SQLite 一致备份，Field 读出实际表名，官方 REA 生成查询证据。若主文件旁还有 WAL 日志，Field 提示先取得一致备份，不把可能缺了最新内容的主文件当完整结果。
- 官方证据能在重连后导入；任务原话和下一步能恢复。改动材料后，旧记录会标为过期。错误输出被独立对照查出，修正后再通过。
- 对两份 Flutter 样本，实际查出各自的类与所属库；只有字符串的材料保持未判定。
- Windows 不再公布本机无法使用的 `inspect_binary_layout`。若官方分析服务无法启动，本地读数、对比和续接仍可用，`review_info` 会报告原因。

在 Windows 五套临时配置中验证了注册、实际服务、移除和配置保全。Claude 客户端实际连接新服务，移除后不再发现它。客户端连接与工具调用验证不等于真实模型对话；尚未验证四个助手的实际对话、完整上游功能、在线首次下载或相对裸助手的表现。日常安装未切换。
