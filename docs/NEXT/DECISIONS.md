# 决策

- D01 独立clone不共享Git对象；冻结1.4.0；迁移前旧仓库和部署只读。
- D02 保留Reverse固定领域正文/路由，不重新实现反编译器。
- D03 REA6.9.0是可追溯核心。增强工具身份独立，原schema/结果/bundle保留。
- D04 去Craft运行依赖和Spec必经门；独立实现选定比较/反馈/清理机制，保留借鉴来源。
- D05 当前宿主唯一推理/编码；不启第二模型，不把全部工具加载为固定流程。
- D06 同一case管理原话、完整目标、依赖、证据、检查和修正；方法按需读取。
- D07 就绪门只阻断依赖未满足的功能；不偷偷降低全量目标。
- D08 比较须独立执行，视觉与行为分开；自有receipt不冒称REA官方proof。
- D09 迭代有预算/新信息判据；unknown保留，不改预期、不无增量重试。
- D10 自有材料对照，不操作旧真实目标；工程性能与模型效果A/B分开。
- D11 新入口不能执行旧安装链；旧资料只追溯，不驱动本轮开发。
- D12 S6前仅隔离配置安装；通过后迁移自有入口并实际验证回退。

- D13 客户端会重排TOML并丢/移动注释。只允许显式旧owner且内容完全相等的旧登记接管；当前同owner精确新版登记可连接/回退，无关字节及末尾孤立注释保留。
- D14 （被D16取代）上一轮发布在旧项目codex/rea-next分支；这不满足用户要求的独立项目。
- D15 工程验收为当前Windows x64 Codex，实际目标验收独立；当前旧聊天工具热加载未通过观察，不冒称已加载。
- D16 用户明确要求独立GitHub项目reverse-fusion-next，旧项目与旧默认分支保留。
- D17 本轮最终复核按FINAL-AUDIT逐项反例检查，不继承旧版或S6的全量完成结论。

- D18 2.3.0使用归属标记和活动OS租约管理临时空间；跨项目按卷预留，连接内周期维护。只回收登记的可重建内容，不按旧目录名称猜垃圾。
- D19 有效不可变证据替代临时来源；来源路径和事件保留为追溯信息，不默认永久占盘。快照失效时保留尚存来源供恢复。
- D20 网络短段按同ETag/位置重试失败段，最终完整摘要不放松；资格使用实际独立clone、自己的资产和精确回退，新测试目录完成即回收。
- D21 2.4.0按生成用途分persistent/reusable/disposable；二级保留/释放由宿主在操作边界据复用价值判断，不另启定时AI。一级禁止降级；旧scratch保持兼容。
- D22 分级不代替活动保护或完整性核对；二级依赖/内容失效只提示重建，不未经宿主决定删除。计时器只回收已声明可删的三级。

- D23 2026-11-18最终形态：本项目提供可选工具/方法/记忆/核对，宿主自主选择是否使用及顺序。D06单case指选择使用本账本时的归属，不要求已有可靠宿主记录再建case。readiness是验收诊断，不是调查/编辑许可。
- D24 内部自动检查、原生REA证明和显式外部宿主审查分开。assessment保存原观察快照、当前对象/输入、上下文/范围/限制及适用期，不写case.checks或官方Evidence。外部未接入自动工具不等于没有证据；宿主审查不认证任意格式来源，也不声称当前服务/设备未变。
- D25 输出协议映射用户原话/补充：analysis-report、independent-reimplementation、specification-implementation、modified-original。技术换路自主，输出类型实质改变按已获用户决定记录；不将修改原程序冒称独立重写、规格测试冒称原版等价。未配置协议继续保守兼容旧目标。
- D26 本轮用户明确不要真实安装/目标测试或模型对话验收；实现后仅静态解析/合同/来源摘要校验，新增回归用例源码不执行。历史179项工程测试不覆盖新源码，不把本轮实现完成宣称正式发布或实际效果已建立。

- D27 2026-11-18用户明确“按此定档”：冻结当前最终形态，转入具体问题维护。定档边界为实现完成/静态校验通过/当前源码运行未验，不等于正式发布、全部功能认证或模型效果证明。停止泛化扩建，不自动安排真实验收；仅据具体缺陷、实际任务阻碍、重复可定位负担或明确新需求继续修改。本次不创建Git标签、不提交推送或切换部署。
