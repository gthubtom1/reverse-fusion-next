# 长任务修复与结论边界

2026-11-17，用户要求依据换肤软件对话查清组件使用、长时低效原因，以及聚合是否限制宿主，并将修复推广到桌面、APK、网页等任务。

原话要点：需要最终总结；确认 REA/Craft/Reverse 实际使用；工具成功不等于用得好；关注未来不同目标的问题，修复通用机制；比较裸模型加工具和聚合的实际价值，不以安装或个别通过代替效果。

本轮保留官方 REA 和工具直达，宿主继续自主判断和编码。不开第二模型循环，不改目标样本，不给所有领域设置固定路线。不宣称穷尽未来目标问题或已经证明优于同模型同工具基线。

| ID | 需要修复的通用缺口 | 本轮可检查的完成条件 |
|---|---|---|
| L01 | 观察证据被工作文件覆盖 | 支持内容寻址的证据副本和显式 live 依赖；源覆盖不毁历史，篡改副本仍失效 |
| L02 | 状态巨大且无法指出行动偏移 | 默认状态不重复回传历史输入快照；列出失效项、未接入检查、过粗功能和重复操作诊断 |
| L03 | 构建/验证游离于统一记录 | 四个增强工具内增加可选的受控命令执行，记录实际耗时、输入/运行环境身份、输出和产物；命令成功不产生验收通过 |
| L04 | 重复成本没有覆盖实际执行 | 已声明可复用且输入/产物均不变的操作复用；同输入反复失败需新信息并有次数边界；不规定 UI/后端统一固定频率 |
| L05 | 验收对象被原版替换 | 明确登记候选和参照身份，声明后交付核对候选产物与身份；原版文件冒作候选遭识别 |
| L06 | 规则压过宿主判断、验证强度失配 | 工作合同说明按任务风险与变化选择检查；独立小功能、局部未知、优先关闭关键差距；截图/打包不作为每次修改的固定阶段 |
| L07 | 旧资格被误读为当前完成 | 当前状态记录新发现和本轮验证；本轮修复与模型效果对照分开，发布前核对受影响源码与合同 |

不将模型填写的成功、截图、外部报告或操作退出零升级为独立比较通过。外部工具报告可以保留为依据；需要验收时使用独立实际比较，避免为了录入状态重复运行已合格的同一增强比较。

完成记录在 JOURNAL 和本文件末尾补充。代码修复完成后运行有针对性的反例，再跑现有工程检查；只有发布相关验证通过后更新本机入口与远端。

待独立评估：同模型、同工具、同目标、同资源预算下的裸宿主与聚合对照。比较需求完成、错误结论、重复操作和成本；本轮机械回归不代替该评估。
