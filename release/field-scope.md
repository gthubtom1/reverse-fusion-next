# 安装内容、证据与原始目标

## 从交件到宿主

1. 压缩包中的 `product/scripts/field-release.json` 选择 Field 配置。解压后运行 `product/scripts/review-host.py`。直接在开发仓库运行同名安装器会按所在目录选择配置。
2. 安装器把总说明、两个上游取证参考及许可证、Field 领域索引与方法说明放进所选宿主。Codex 和 Pi 使用自己的服务配置，Claude Code 使用插件目录内的登记，OpenCode 按主要版本使用对应的配置结构。归属记录用于检查、移除和保留用户的其他配置。
3. 实际登记指向当前 Python 和解压目录中的 `scripts/field-service.py mcp`。REA 和 Node 使用包内锁定的版本，按需准备在产品目录。九个公开工具如下。宿主负责编写成品、保存文件和在用户授权范围内进行行为观察。

| 公开工具 | 来源、输入和输出 |
|---|---|
| `review_info` | Field 配置、版本和输入限制。显式给出元数据文件时可核对其声明。 |
| `review_summary`、`review_compare` | Field 读取本地 REA 导出的结构或按记录 ID 对比内容。输出绑定输入摘要。 |
| `review_rea_import`、`review_rea_compare` | 用原始输入字节的临时副本调用固定官方 `evidence-import`、`compare`。返回官方结果、退出码、原始输出和输入身份。 |
| `field_rea_identify` | 对受支持的 UTF-8 XML plist 调用官方 `inspect-artifact`。核对根文件、两条证据、关联、大小和摘要，再重导。主机可把 Base64 解码成原档案。已取得导出而重导失败时，保留已校验的原档案，标注重导未验证。 |
| `field_observe` | Field 的本地静态读数，包括 APK 编译清单、PE/ELF 头、约定范围内的 COFF、ZIP、网页、SQLite 模式、录制帧及业务材料等。Flutter 专项使用 `detail=flutter-package-classes`，在选定 ARM64 库中按引用连接类与 Dart 库，返回本次输入和读取器摘要。 |
| `field_compare_files` | 对两个本地资源包或受支持文件静态比较。将两侧摘要、成员差异或字段变化供宿主引用。 |
| `field_decode_records` | 按同版本手册解码字段，保留映射行、单位解释所需信息及两份输入的摘要。含未确认数量时区分已知小计与整批总数。 |

完整 REA 发行物会准备到本机，其中包含官方工具、方法与证据格式说明。Field 向宿主登记的是上表的接口。官方完整 Evidence 阅读说明位于该依赖的 `skills/reverse-engineer-anything/references/evidence-workflows.md`。证据页与完整记录可用各自的 ID 区别，判断范围取自相应记录。Field 的进口操作使用独立临时目录，长期交接请保存导出字节、摘要和来源。

## 仓库里还有什么

| 仓库位置 | 与本次发行的关系 |
|---|---|
| `skills/`、`components/reverse-core/` | 仓库保管原领域资料和路由。Field 挂载两篇上游取证参考，通过自有索引按需读取十一篇 Field 方法。完整路由、其余原领域和各自外部依赖仅在仓库范围内。 |
| `rea_enhanced/`、`components/rea-enhanced/` | 安装所用的下载、文件归属和锁辅助模块随包。通用案例管理、状态恢复、独立比较服务、专业提供程序、空间维护与迁移入口保留在仓库。有辅助源码随包的功能也须以实际注册入口为准。 |
| `components/craft-*/`、`vendor/craft/`、`vendor/spec-kit/` | 相关历史实现和参考材料保存在仓库。Field 采用宿主执行的独立比较方法，安装链依赖为 Python、Node 和官方 REA。 |
| `components/field-kit/flutter-inventory/` | 包内是指定摘要的 Windows 读取器及声明。包装入口、Go 构建入口和固定的解析器源码快照在仓库。专项限于支持的 ARM64 发布库的静态类归属。 |

## 原始目标与证据边界

| 原要求 | 本版静态结论和已有依据 |
|---|---|
| N01–N02、N20，独立项目、恢复与用户入口 | 原始目标已写入恢复说明和状态。Windows x64 只有一个当前推荐包。本次没有实际安装到新机。 |
| N03–N05、N17，领域知识、官方核心、专业工具 | 上表列出实际入口。1.1.18 有官方归档重新导入和移动库清点记录。完整 REA 工具面、完整 Reverse 路由、各专业工具从新原件产生结果，均未获 Field 整体验证。 |
| N06–N07、N12，宿主自主，Craft 和 Spec 为可选参考 | 发行源码的安装与启动链没有 Craft、Spec 和第二个模型依赖。新版本宿主的实际选择和行为未验证。 |
| N08–N11，保留原话、证据和成果类型 | 入口指引尊重用户要求。通用案例状态与跨对话接续没有接入 Field 服务。跨项目恢复、所有资料不完整时的交付表现未验证。 |
| N13–N15、N18，独立比较、差异与修正 | 旧版已有小型网页及业务修复对照、候选库存缺值记录。任意桌面、移动、扩展及有后台服务的完整复刻，所有原件与新版本行为等价，以及对裸宿主的普遍增益均未验证。 |
| N16、N19，边界、资源、安装与回退 | 上一版有隔离装卸及回退回执，曾有空缓存首装超时。Field 的输入、输出及调用时限可静态核对。全项目磁盘生命周期、默认 IDA 插件的全部写入位置、1.1.19 实际升级回退均未验证。 |
| 依赖真机、服务或其他专项的原始目标 | 真机启动、线上身份生效、现场设备与无线状态需对应运行观察。Binary Ninja 原生读数及原范围的攻防专项仍未签收。 |

本次源码改动均随产品封入。历史实测收在同级的“既有证据”目录。文件清单记录各产品文件的仓库来源及摘要。所有运行结论沿用各自的原始范围，本版静态定稿已结束，自动续做任务为空。
