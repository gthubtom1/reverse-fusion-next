# Autonomous host + optional Reverse/REA support

The host chooses tools, methods and order from the user's goal and evidence. Reverse offers on-demand knowledge; official REA offers tools/Evidence. Routes/adapters are not required controllers. No Craft runtime, mandatory Spec or product-internal model loop.

Use native or other suitable tools directly. No mandatory case, route, workitem, fixed order or per-command bookkeeping. Reuse reliable host records instead of duplicating them. Ordinary development stays native; simple analysis may end with observations/report. Use the optional case/checkpoint only when it helps retention/recovery. Preserve original wording, supplements and remaining work somewhere reliable.

Investigate the current gap. Protection, entitlement, packing, missing runtime material and remote dependencies are conditions to examine, not fixed instructions to bypass, dump or immediately rebuild. Static/dynamic/device work and implementation may alternate. Change route with evidence; continue unaffected work. Ask about user-only material or substantive output choices, not routine methods.

Readiness is an acceptance diagnostic, never permission to investigate or edit. Select validation by question, not component. External professional/device/project observations can receive explicit host review with saved evidence, current artifact/input bindings, scope and limits. This is not automatic pass or official REA proof. Unsupported automation differs from absent evidence; arbitrary JSON never grants native/internal pass.

Distinguish analysis, independent source, specification implementation and modified-original outputs. Keep the agreed goal; a patched original is not independent source. Tracked delivery maps allowed kinds to user wording. Technical route changes are autonomous; substantive output changes need an explanation and agreement where not already covered.

Do not turn guesses, exit zero, pixels or structure into broader verified behavior. Related changes invalidate results. Reuse valid observations; retries need new information and bounded effort. Separate observed, implemented, automatic verification, host review, delivery and missing. Partial delivery keeps remaining goals. Preserve official bundles/IDs/unknowns; label owned receipts.

Large outputs: docs/DISK-MANAGEMENT.md. Preserve originals/evidence, justify reuse, reclaim disposable work after users stop. Protect active/referenced data and unrelated folders. Tools own descendants, not an OS sandbox.

Operations: docs/AGENT-WORKFLOW.md and COMPARISON.md; methods: DOMAIN-METHODS.md. Start at the repository README. Use fusion.py for the current source candidate; field.py is the retained Field profile. Preserve config/credentials and rollback. Active docs: docs/ACTIVE-DOCUMENTS.json. Engineering checks do not prove model superiority or arbitrary-target success.
